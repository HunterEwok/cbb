# 工作原理

写给想了解复制内容会经历什么，以及 Connect Beyond Borders 如何连接各台设备的人。Connect Beyond Borders 在你自己的设备之间共享同一个剪贴板，不需要账号、云服务或中央服务器。

设置步骤见[快速入门](quickstart.md)。工程细节和传输格式见[设计文档](../design.md)和[协议](../protocol.md)。

## 复制时会发生什么

当你在某台设备上复制文字、图片或文件时，Connect Beyond Borders 会为你的其他设备加密这份内容，然后通过家庭网络发送出去；当你不在家时，则通过群组自己的加密隧道发送。

每台设备收发复制内容的方式，取决于操作系统允许的权限：

- **电脑和小型设备**：复制后会自动将内容发送到群组；只要**同步**处于开启状态，收到的复制内容也会自动写入剪贴板。
- **Android 手机**：应用会在后台自动接收复制内容。要发送复制内容，可以开启应用的无障碍服务以自动发送，也可以点按应用里的同步按钮。
- **iPhone、Aurora OS 和 HarmonyOS 手机**：移动操作系统限制后台访问剪贴板。应用在屏幕上打开时，它会像电脑一样自动监听。当你使用同步按钮或手势（例如 iPhone 上的操作按钮或轻点背面）时，手机会将自己的剪贴板与群组的最新复制内容互换。如果手机剪贴板为空，它会直接接收群组的复制内容而不会覆盖。

Connect Beyond Borders 分层保护每一份复制内容：

- **端到端加密**：在复制内容离开你进行复制的设备之前，该设备会只为群组中读取复制内容的设备加密（封装）这份内容，并用自己的密钥签名。封装后的内容会在加密连接（TLS 1.3）中传输，连接双方会相互验证对方的密钥。只负责传递复制内容的设备以及群组之外的任何服务器，都无法读取、篡改或伪造复制内容。
- **文字、图片和文件**：纯文本直接随同步消息传输。当你复制图片、文件或带格式文本时，复制的设备会先发出一则简短通知，各接收设备再按各自的大小上限拉取封装后的内容。详见[图片、文件和带格式文本](images-and-files.md)和[限制与有效期](../reference/limits.md#copies)。
- **密码和机密**：Connect Beyond Borders 会跳过密码管理器标记为机密的项目。你主动发送的机密内容只保存在内存中，会在较短的有效期后过期（默认 60 秒），到期后会从剪贴板中清除。
- **无剪贴板历史**：Connect Beyond Borders 不保留过去的复制历史。每份复制内容都带有全群组统一的有效期（普通内容默认 5 分钟，机密内容默认 60 秒）。超过有效期后，设备便不再将该内容写入剪贴板。
- **暂停同步**：每台设备都有一个**同步**开关。关闭**同步**后，剪贴板只留在本机，同时设备仍保持与群组的连接。如果某台设备的剪贴板行为异常，管理员也可以将其静音。

## 群组

你的设备组成一个**群组**，共用同一个剪贴板。每台设备都保存一份群组的已签名设备记录，其中列出了群组里的每台设备、它的角色以及所有已移除的设备。因为每台设备都会自行验证这些签名记录，你的群组不需要中央服务器。

一个群组属于一个人。两个人如果希望各自拥有独立的剪贴板，可以创建两个群组。

只有经你通过配对码或二维码批准的设备，才能加入你的群组。如果你丢失了某台设备，将其移除后会向群组传播一份已签名的移除记录，其他设备会立即拒绝它。详见[设备丢失怎么办](lost-device.md)。

每台设备在群组中都有一个角色：

| 角色 | 哪些设备 | 做什么 |
|---|---|---|
| **主设备**（在命令行工具和图示中称为 *root*） | 创建群组的手机，或[不使用应用](without-app.md)时使用的电脑 | 保管群组的主密钥，添加和移除设备，指定管理员，并设定群组规则 |
| **管理员** | 主设备选定的另一部手机或一台电脑 | 添加和移除普通设备，冻结被盗的管理员电脑，并发送[远程粘贴](remote-paste.md)等管理操作；管理员手机还可以移除另一名管理员 |
| **成员** | 每台电脑、手机和小型设备（例如路由器或 Raspberry Pi；见[小型设备](../../member/README.md)） | 同步剪贴板 |
| **无 root 成员** | 不使用管理员权限（`sudo`）安装的 Linux 电脑 | 像普通成员一样同步，但不能成为主设备、管理员或中心节点（[无 root 成员](#rootless-members)） |
| **中心节点** | 家中的一台电脑、路由器或小型开发板 | 在设备离家时连接它们；只转发复制内容的中心节点不会读取任何内容 |

已配对的 Apple Watch、Wear OS 手表或 HarmonyOS 手表会通过对应手机显示群组设备，并开关离家同步；详见[各平台应用](apps.md)。

设备保存密钥的位置，决定了设备被盗时窃贼能拿走什么：

- **手机**在安全硬件内生成密钥——iPhone 上的安全隔区（Secure Enclave）、Android 密钥库（StrongBox 或 TEE）、Aurora OS 上的安全元件，或 HarmonyOS 上的 HUKS——且密钥始终留在其中。签署管理变更时需要验证你的面容、指纹、密码，或（在 Aurora OS 上）应用自己的 PIN 码；日常同步无需验证即可工作。
- **电脑**会在硬件可用时将成员密钥和管理员密钥保存在硬件中：配备 Apple 芯片或 T2 芯片的 Mac 使用安全隔区（Secure Enclave），Linux 和 Windows 电脑使用硬件安全芯片（TPM）；充当主设备的电脑也会把主密钥保存在其中。没有这类硬件的电脑和小型设备，则将密钥保存在只有 Connect Beyond Borders 能读取的文件中。

关于密钥存储和验证的完整说明，见[密钥与认证](keys.md)。

### 无 root 成员

常规 Linux 安装会请求一次管理员权限（`sudo`），让 Connect Beyond Borders 在独立的系统账户和严格的沙箱中运行。这种隔离可防止浏览器、游戏和其他程序读取你设备的密钥。

在没有 `sudo` 权限的 Linux 电脑上（例如工作电脑），无 root 安装会在你自己的用户账户下运行。它可以像任何成员一样同步，但你运行的任何程序都能复制它的密钥文件并冒充这台设备。因此，无 root 成员永远不能成为主设备、管理员或中心节点。设备列表会将其标为**成员，无 root 权限**。

Steam Deck 支持常规安装，因为其用户拥有 `sudo` 权限；详见[在 SteamOS 上安装](install.md#steamos-steam-deck)。

## 两种群组

群组可以包含至少一台电脑或小型设备，也可以只由手机组成。两种方式都能正常工作，你也可以随时向纯手机群组中添加电脑。

| | 包含电脑或小型设备 | 仅手机 |
|---|---|---|
| 主设备 | 手机（密钥在安全硬件中），或[不使用应用](without-app.md)时的电脑 | 手机（密钥在安全硬件中） |
| 在家同步 | 在家庭网络中直接加密连接 | 应用运行时通过盲中继 |
| 离家同步 | 通过充当中心节点的电脑或小型设备 | 应用运行时通过盲中继 |
| 需要的额外设备 | 一台电脑、路由器或小型开发板 | 无 |

手机只会发起传出连接，因为移动操作系统不允许应用在后台等待传入连接。电脑和小型设备则会监听传入连接。

加入一台保持开机的电脑——例如台式机、家庭服务器、路由器或 Raspberry Pi——即可在本地直接同步，完全无需任何服务器。你也可以在应用里打开该电脑的设备页，将它设为中心节点，这样即使手机应用已关闭，离家同步也能继续工作。

## 在家

在同一个家庭网络中，你的设备会通过本地网络发现（mDNS）自动找到彼此，并通过加密的 TLS 1.3 连接直接通信。所有内容都不会离开你的网络，设备之间也没有服务器。你可以关掉任意设备，其余设备仍会继续同步。

![在家时，手机、笔记本、台式机和 Raspberry Pi 通过 mDNS 相互发现并建立加密直连，中间没有任何服务器](../images/at-home.svg)

家庭本地直接同步要求网络中至少有一台电脑或小型设备，因为手机只会发起传出连接。

**已知家庭网络**：电脑会记住它与群组相遇过的家庭网络（由网络及其路由器识别）。在陌生网络上（例如咖啡馆或酒店 Wi-Fi），电脑会保持静默：既不在本地网络上宣告自己，也不接受传入连接。

**家中的独立网络**：本地网络发现（mDNS）不会跨越连接不同本地网络的路由器，例如单独为智能设备划分的网络。你可以通过三种方式连通两个家庭网络：

- 在同时连接两个网络的路由器上运行 Connect Beyond Borders。
- 为电脑或小型设备指定另一网络中某台电脑的地址（[小型设备](../../member/README.md#install)）。
- 通过中心节点连接两个网络（[离家：中心节点](#away-from-home-the-hub)）。

## 离家：中心节点

当笔记本或手机离开家庭网络时，它无法通过本地发现找到家里的设备。为了继续同步，家里的一台电脑、路由器或小型开发板会充当**中心节点**：离家的设备通过群组自己的加密隧道（WireGuard）连回中心节点，再由中心节点在离家设备与家中设备之间传递复制内容。

![离家时，笔记本和手机通过群组的 WireGuard 隧道连接到家中的中心节点，中心节点再与家庭网络中的台式机和 Raspberry Pi 同步](../images/hub.svg)

在 WireGuard 隧道内部，设备运行着与在家时相同的双向 TLS 连接和端到端封装复制。隧道运行在 Connect Beyond Borders 内部：它只承载 Connect Beyond Borders 的流量，不会占用手机的 VPN 插槽，因此你自己的 VPN 仍可正常使用。

你可以在两种中心节点之间选择：

- **读取复制内容的中心节点**：你的主设备（如果是电脑）或一台管理员电脑。其他设备会像对待普通读取设备一样为它封装复制内容，群组的[密钥级别](keys.md#the-three-levels)也适用于它的密钥。
- **只转发复制内容的中心节点**：由主设备选定的普通电脑或小型开发板（例如 Raspberry Pi 或 NAS）。其他设备会绕过它进行端到端封装，因此它不会读取任何复制内容，也不会自行生成复制内容，且不需要硬件安全芯片。

中心节点的关键特性：

- **直接访问中心节点**：你的路由器将一个 UDP 端口（默认 8764）转发给中心节点，或者你的家庭网络提供直接的 IPv6 访问。
- **中心节点关机时**：中心节点关机期间离家同步会暂停，而在家的设备仍会直接同步，不受影响。
- **在家完成设置**：设备会在家庭网络中与中心节点交换隧道密钥，因此请在出门前开启**随处**（离家同步）。
- **多个中心节点**：一个群组可以按固定优先级设置多个中心节点。同一时间只有优先级最高的在线中心节点提供服务；备用中心节点不建立隧道并保持待命，一旦当前活动的中心节点停止或离线超过一分钟，备用中心节点就会自动接管。

设置步骤见[离家使用](away-from-home.md)。

## 位于运营商 NAT 之后：转发器

许多互联网服务商把家庭网络放在共享公网地址后面（运营商级 NAT），即使做了端口转发，外部传入连接也无法到达你家。在这种情况下，你的中心节点会向**转发器**注册——转发器是互联网上的一台服务器，负责在你的离家设备和中心节点之间中转加密的隧道数据包。因为是由中心节点主动向转发器发起传出连接，你无需在路由器上开放任何端口。

![位于互联网服务商 NAT 之后的中心节点主动向转发器发起传出连接，转发器在离家的笔记本和手机与家中的中心节点之间传递加密隧道数据包](../images/forwarder.svg)

转发器不持有任何群组密钥，也无法读取你的剪贴板。它只负责在你的离家设备和中心节点之间转发加密的 WireGuard 数据包。

你可以选择以下两种转发器之一：

- **你自己的转发器**：部署在任何有公网地址的服务器上，例如一台小型虚拟服务器（[运行自己的服务器](../admin/self-hosting.md#a-forwarder)）。
- **项目的转发器**：位于 `cbb.tools`，其地址和密钥内置于 Connect Beyond Borders 中，并通过已签名的列表保持更新。

设备会优先尝试中心节点的直接地址，只有在直连没有响应时才使用转发器。

## 屏蔽 VPN 的网络

部分酒店和办公室 Wi-Fi 网络、移动运营商以及某些国家会屏蔽标准 WireGuard 流量。默认情况下，中心节点会伪装其隧道，让连接得以通过：

- **AmneziaWG**：随机化数据包头并添加填充，使隧道在网络传输中看起来不像 WireGuard。
- **VLESS**（使用转发器时）：将伪装后的隧道承载在看起来像访问转发器网站的普通 HTTPS 连接中。

设备会先尝试速度更快的 UDP 上的 AmneziaWG，在 UDP 被屏蔽时再切换到 HTTPS 上的 VLESS。启用 VLESS 后，设备绝不会回退到普通 WireGuard，因此过滤网络不会看到未伪装的 VPN 流量。

电脑、小型设备（MIPS 路由器除外，这类设备仅支持在家同步；见[设备、端口和文件](../reference/devices.md)）以及所有手机应用都支持 AmneziaWG 和 VLESS。无论隧道如何伪装，复制内容始终位于 WireGuard、双向 TLS 和端到端加密的保护之下。要修改这些设置，见[屏蔽 VPN 的网络](blocked-networks.md)和[命令](../reference/cli.md)。

## 没有中心节点：盲中继

手机永远不能充当中心节点：手机会休眠、切换网络，无法可靠地接受后台连接。当群组里没有电脑、路由器或小型开发板充当中心节点时（例如仅由手机组成的群组），设备会在**盲中继**上会合。

![离家的笔记本与家中的 Mac 通过隧道连接到盲中继，两台设备之间直接进行端到端加密](../images/relay.svg)

盲中继只是一个会合点，而不是群组成员。每台设备都会向中继建立一条加密隧道，中继将同一群组的两台设备连接起来，让它们的双向 TLS 和端到端封装复制直接在彼此之间进行。中继无法读取你的剪贴板，也无法冒充任何设备。

由于盲中继不存储任何内容，两台设备必须同时在线才能交换复制内容。电脑和所有手机应用都可以使用盲中继——无论是项目在 `cbb.tools` 上开放的中继，还是你自己服务器上的中继。主设备只有在征得你同意后才会为群组开启盲中继。详见[离家使用](away-from-home.md#no-computer-for-a-hub)和[运行自己的服务器](../admin/self-hosting.md#a-blind-relay)。

## 各类服务器能看到什么

转发器和盲中继都不会收到你群组的设备列表、设备名称或永久设备 ID。相反，群组会生成临时的**服务器凭据**——每个服务器各有一套独立的凭据——并大约每月更换一次（移除设备时会立即更换）。每个服务器只能看到该周期内的临时随机标识符（化名），两个服务器之间无法将你群组的流量关联起来。

| 服务器 | 读取剪贴板 | 知道哪些设备在通信及何时通信 | 运营方 |
|---|---|---|---|
| 读取复制内容的中心节点 | 是（它是你自己的主设备或管理员电脑） | 是 | 你 |
| 只转发复制内容的中心节点 | 否（复制内容绕过它封装） | 是（可看到发送方、时间和取整后的大小） | 你 |
| 转发器 | 否 | 否（可看到与你的中心节点交换加密数据包的网络地址、数据包时间和大小） | 你，或项目在 `cbb.tools` 上运营的 |
| 盲中继 | 否 | 是（可看到同时在线的临时设备化名、它们的网络地址、时间和流量） | 你，或项目在 `cbb.tools` 上运营的 |

Connect Beyond Borders 不使用账号、不使用云存储，也没有遥测。关闭离家同步时，电脑上的服务只在你的家庭网络内通信。开启离家同步时，服务只与你的家庭网络以及群组自己的中心节点、转发器和中继通信。程序在每个系统上都会强制执行这一边界，Linux 和 Windows 还会借助系统网络规则进一步强制限制。

当手机应用关闭且开启了通知时，你的设备可以通过 `cbb.tools` 和手机的推送服务发送一则加密封装的推送通知来唤醒手机。只有你的手机能打开该通知；两边推送服务都无法读取你的复制内容。

如需了解其他各方（如你的 Wi-Fi 网络、更新检查和应用商店）能看到哪些信息的完整列表，请阅读[隐私：谁能看到什么](privacy.md)。完整的技术规范见[设计文档](../design.md)和[协议](../protocol.md)。
