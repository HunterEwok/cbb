# רשתות שחוסמות VPN

מחוץ לבית המכשירים שלכם מגיעים אל הרכזת דרך מנהרת ה-WireGuard של הקבוצה עצמה. יש רשתות שחוסמות את WireGuard: ה-Wi-Fi של מלונות ומשרדים, חלק ממפעילי הסלולר, ומדינות שלמות שמסננות VPN. ל-Copy Beyond Borders יש שתי דרכים לעקוף זאת. שתיהן מופעלות ברכזת, והמכשירים קולטים אותן בפעם הבאה שהם פוגשים את הרכזת בבית.

| דרך | מה הרשת רואה | מה צריך | עובדת ב |
|---|---|---|---|
| WireGuard רגיל (ברירת מחדל) | חבילות WireGuard | הרכזת או מעביר | מחשבים, טלפונים, חבר קל |
| **AmneziaWG** (‏`-obfuscate`) | חבילות UDP שלא נראות כמו שום דבר מסוים | הרכזת או מעביר | מחשבים, טלפונים |
| **VLESS** (‏`-vless`) | חיבור HTTPS לאתר | מעביר עם VLESS מופעל (בזה של הפרויקט הוא מופעל) | מחשבים, טלפונים |

לא משנה מה תבחרו, לוח ההעתקה נשאר בתוך מנהרת הקבוצה וה-TLS של המכשירים עצמם, כך ששום דבר בין המכשירים שלכם לא יכול לקרוא אותו. ההסוואה משנה רק את המראה של החבילות ברשת.

## באיזו להשתמש

1. נסו קודם **WireGuard רגיל**. הוא המהיר ביותר ועובד ברוב הרשתות.
2. אם המנהרה לא עולה ברשת מסוימת, או נחתכת אחרי זמן מה, הפעילו **AmneziaWG**. רוב המסננים שמחפשים WireGuard כבר לא מזהים אותו.
3. אם גם זה חסום, כמו במדינות שחוסמות כל סוג תעבורה לא מוכר, השתמשו ב-**VLESS**. הוא צריך מעביר שמקבל VLESS ביציאת TCP 443: זה של הפרויקט ב-cbb.tools מקבל, או מעביר משלכם.

שום דבר לא עוזר ברשת שמעבירה רק רשימה של כתובות מאושרות.

## AmneziaWG

ברכזת:

```sh
sudo cbb global hub -obfuscate 203.0.113.7:8764
```

עם מעביר, הוסיפו `-obfuscate` באותה דרך:

```sh
sudo cbb global hub -obfuscate -forwarder 198.51.100.9:8764 -forwarder-key <key>
```

הרכזת יוצרת את הגדרות הקבוצה פעם אחת, באקראי, ושומרת אותן כל עוד `-obfuscate` נשאר. אחר כך הביאו כל מחשב נייד וטלפון הביתה פעם אחת, או השאירו את האפליקציה פתוחה בבית, כדי שיקלטו את ההגדרות החדשות. החבר הקל מדבר רק WireGuard רגיל: בקבוצה עם ערפול הוא מסתנכרן רק בבית.

## VLESS

‏VLESS פועל בין המכשירים שלכם לבין המעביר, בתוך מה שנראה לרשת כמו חיבור HTTPS רגיל לאתר.

1. **המעביר.** במעביר של הפרויקט ב-cbb.tools‏ VLESS מופעל: בעיני הרשת, המכשירים שלכם מבקרים ב-`cbb.tools`. מעביר משלכם מריץ אותו באחת משתי דרכים:

   ```sh
   cbb forward -vless-xhttp vpn.example.org   # behind your site's web server
   cbb forward -vless-site www.example.com    # REALITY, on a server without a site
   ```

   מאחורי שרת אינטרנט שיש לו את התעודה של האתר שלכם, שרת האינטרנט מעביר אליו את הנתיב שהמעביר מדפיס. ‏REALITY שואל את ה-TLS של אתר גדול, ומי שמתחבר בלי מפתחות הקבוצה, למשל צנזור שבודק אותו, מקבל את הדפים של אותו אתר: בחרו אתר שאינו חסום במקום שאליו אתם נוסעים ותומך ב-TLS 1.3, ופתחו את TCP 443 בחומת האש של השרת, לצד UDP ו-TCP 8764. הכנת השרת מתוארת ב[הפעלת שרתים משלכם](../admin/self-hosting.md#vless-on-the-forwarder).

2. **ברכזת**: הפעילו VLESS באפליקציה (המנהרה של הרכזת: VLESS), או:

   ```sh
   sudo cbb global hub -forwarder default -vless
   ```

   (‏`-forwarder 198.51.100.9:8764 -forwarder-key <key>` למעביר משלכם.) המעביר אומר לרכזת באיזו דרך הוא פועל. הוסיפו גם `-obfuscate` אם תרצו; אז שניהם חלים.

3. **במכשירים**: פגשו את הרכזת בבית פעם אחת, כמו אחרי כל שינוי. מאותו רגע הם מגיעים אל המעביר רק דרך VLESS, אף פעם לא קודם עם WireGuard רגיל, ולכן הרשת שממנה אתם רוצים להסתיר את המנהרה לא רואה אותה לעולם.

## עצות למדינות שמסננות

- **הגדירו הכול בבית, לפני הנסיעה.** המכשירים לוקחים את הגדרות הרכזת רק ברשת הביתית.
- בחרו מעביר מחוץ למדינה שמסננת, אצל ספק אירוח שאינו חסום שם.
- ב-VLESS עם REALITY, בחרו אתר שאנשים באותה מדינה משתמשים בו כל יום, כך שחסימתו תפגע בהם; ואתר שמוגש מספק אחר מזה של המעביר שלכם.
- ה-VPN של הטלפון עצמו ממשיך לעבוד: המנהרה של האפליקציה היא תעבורה רגילה של האפליקציה ואינה תופסת את מקום ה-VPN של הטלפון.
- אם המנהרה מפסיקה לעבוד בנסיעה, `cbb global` במחשב נייד אומר מה נכשל, ו-`CBB_DEBUG=1` מראה את הפרטים ([פתרון בעיות](troubleshooting.md#sync-away-from-home)).
