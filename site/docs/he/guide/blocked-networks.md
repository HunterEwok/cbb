# רשתות שחוסמות VPN

למי שמסנכרן מחוץ לבית ברשתות שמסננות או חוסמות את WireGuard, כמו Wi-Fi של מלונות, רשתות משרדיות, מפעילי סלולר או מדינות עם סינון תעבורה מחמיר. בדף הזה תוכלו לבדוק או לשנות את האופן שבו הרכזת שלכם מסווה את המנהרה שלה.

מחוץ לבית, המכשירים שלכם מגיעים אל הרכזת דרך מנהרת ה-WireGuard של הקבוצה שלכם. כברירת מחדל, רכזת משתמשת גם ב-**AmneziaWG** וגם (כאשר היא משויכת למעביר שתומך ב-VLESS) ב-**VLESS**, כדי שהמנהרה שלכם תעבור דרך רשתות מסננות. ללא קשר להסוואה, ההעתקות שלכם נשארות בתוך WireGuard, בתוך TLS 1.3 הדדי ובהצפנה מקצה לקצה; ראו [איך זה עובד](how-it-works.md#networks-that-block-vpns).

| תעבורה | מה הרשת רואה | דרישות | מכשירים נתמכים |
|---|---|---|---|
| **AmneziaWG** (מופעל כברירת מחדל) | חבילות UDP עם כותרות וריפוד אקראיים | רכזת או מעביר | מחשבים, מכשירים קטנים (מלבד נתבי MIPS), טלפונים |
| **VLESS** (מופעל כברירת מחדל עם מעביר VLESS) | חיבור HTTPS לאתר של המעביר | מעביר עם VLESS מופעל (במעביר של הפרויקט ב-`cbb.tools` הוא מופעל) | מחשבים, מכשירים קטנים (מלבד נתבי MIPS), טלפונים |
| **WireGuard רגיל** (`-no-obfuscate -no-vless`) | חבילות WireGuard UDP תקניות | רכזת או מעביר | מחשבים, מכשירים קטנים (מלבד נתבי MIPS), טלפונים |

## איך המכשירים בוחרים

כשרכזת משתמשת במעביר שתומך ב-VLESS, מכשירים מחוץ לבית מנסים קודם **AmneziaWG** על גבי UDP, כי UDP מהיר יותר במקום שבו הרשת מתירה אותו. אם UDP חסום — כמו ברשתות שמתירות רק תעבורת אינטרנט — הם עוברים אוטומטית אל **VLESS** על גבי HTTPS (יציאת TCP 443) אל המעביר, ונשארים עם אמצעי התעבורה שהצליח.

כש-VLESS מופעל, המכשירים לעולם לא חוזרים ל-WireGuard רגיל, כך שרשתות מסננות אינן רואות תעבורת VPN לא מוסווית. רכזת בלי מעביר מציעה AmneziaWG בלבד.

שום הסוואת מנהרה לא עוזרת ברשת שמתירה חיבורים רק לרשימה קבועה של כתובות IP או דומיינים מאושרים.

## הגדרת הסוואת המנהרה באפליקציית שולחן העבודה

ברכזת שמריצה את אפליקציית ה-Mac או את אפליקציית מגש המערכת ל-Linux ול-Windows:

1. פתחו את **CBB** ובחרו בדף המכשיר של המחשב הזה.
2. תחת **רשתות מחמירות**, הפעילו או כבו:
   - **רשתות שחוסמות VPN (AmneziaWG)** כדי להפעיל או לכבות את AmneziaWG.
   - **רשתות שמעבירות רק תעבורת אינטרנט (VLESS)** כדי להפעיל או לכבות את VLESS (דורש מעביר שתומך ב-VLESS).
3. אשרו באמצעות סיסמת מנהל המערכת, Touch ID,‏ Windows Hello או בקשת polkit.
4. חברו כל מחשב נייד וטלפון לרשת הביתית שלכם פעם אחת כדי שיקבלו את הגדרות המנהרה המעודכנות של הרכזת.

**תוצאה:** הרכזת שומרת את ההגדרות המעודכנות ומשתפת אותן עם המכשירים שלכם בפעם הבאה שהם נפגשים בבית.

## AmneziaWG

כל רכזת מפעילה את AmneziaWG כברירת מחדל ברגע שמגדירים אותה:

```sh
sudo cbb global hub 203.0.113.7:8764
```

הרכזת יוצרת פרמטרים אקראיים של AmneziaWG עבור הקבוצה שלכם ומחליפה אותם אוטומטית בכל תקופת אישורי שרת (בערך פעם בחודש), תוך שיתוף הסט הבא מראש.

כדי לעבור ל-WireGuard רגיל ברשתות שבהן שום דבר לא חוסם VPN (מה שמפחית את התקורה של החבילות):

1. הריצו ברכזת (השתמשו ב-`-keep` כדי לשמור על הכתובות והמעביר הקיימים של הרכזת):

   ```sh
   sudo cbb global hub -keep -no-obfuscate -no-vless
   ```

2. חברו כל מחשב נייד וטלפון שנמצאים מחוץ לבית אל הרשת הביתית שלכם פעם אחת (השאירו את אפליקציית הטלפון פתוחה לרגע) כדי שיקבלו את ההגדרות החדשות.

**תוצאה:** המכשירים שלכם משתמשים ב-WireGuard רגיל ברגע שהם קולטים בבית את ההצעה המעודכנת.

## VLESS

VLESS מעביר את המנהרה המוסווית ב-AmneziaWG בתוך מה שנראה לרשת כמו חיבור HTTPS רגיל לאתר של המעביר. השארת AmneziaWG בתוך VLESS מסתירה גדלים של חבילות WireGuard שאחרת היו עלולים לבלוט בתוך HTTPS.

1. **בחרו מעביר עם VLESS:**
   - **במעביר של הפרויקט ב-`cbb.tools`** כבר מופעל VLESS; בעיני הרשת, המכשירים שלכם נראים כאילו הם מבקרים ב-`cbb.tools`.
   - **מעביר משלכם:** הריצו את `cbb forward` מאחורי שרת אינטרנט שמחזיק את תעודת ה-TLS של האתר שלכם:

     ```sh
     cbb forward -vless-xhttp vpn.example.org
     ```

     הגדירו את שרת האינטרנט שלכם להעביר (proxy) את הנתיב ש-`cbb forward` מדפיס אל המאזין המקומי של המעביר (`127.0.0.1:3276` כברירת מחדל), תוך הגשת דפי האתר שלכם לכל השאר. פתחו את **יציאת TCP 443** בחומת האש של השרת לצד יציאות UDP ו-TCP 8764. ראו [הפעלת שרתים משלכם: VLESS במעביר](../admin/self-hosting.md#vless-on-the-forwarder).

2. **כוונו את הרכזת אל המעביר:** ברכזת, הירשמו אל המעביר של הפרויקט או אל המעביר שלכם:

   ```sh
   sudo cbb global hub -forwarder default
   ```

   עבור מעביר משלכם, העבירו במקום זאת את הכתובת והמפתח שלו:

   ```sh
   sudo cbb global hub -forwarder 198.51.100.9:8764 -forwarder-key KEY
   ```

   **תוצאה:** הרכזת מבקשת VLESS אוטומטית. אם המעביר תומך ב-VLESS, הוא שולח לרכזת את שם האתר ואת הנתיב שלו; אחרת הרכזת נרשמת ל-UDP בלבד. כדי לכבות את VLESS תוך שמירה על AmneziaWG, העבירו `-no-vless` (לדוגמה, `sudo cbb global hub -keep -no-vless`).

3. **סנכרנו פעם אחת בבית:** חברו כל מחשב נייד וטלפון לרשת הביתית שלכם (ופתחו את אפליקציית הטלפון לרגע) אחרי שינוי הגדרות הרכזת.

   **תוצאה:** המכשירים שלכם מקבלים את הצעת ה-VLESS של הרכזת ומשתמשים בה אוטומטית בכל פעם ש-UDP חסום.

## עצות למדינות שמסננות תעבורה

- **הגדירו ובדקו בבית לפני הנסיעה.** המכשירים מקבלים את הגדרות המנהרה של הרכזת רק ברשת הביתית שלכם.
- **ארחו את המעביר שלכם מחוץ למדינה המסננת** אצל ספק שכתובות ה-IP שלו אינן חסומות שם.
- **היערכו לחסימת דומיין:** שם הדומיין של המעביר מופיע בלחיצת היד של TLS (SNI). אם רשת חוסמת את `cbb.tools`, הריצו מעביר משלכם מאחורי שם דומיין אחר.
- **השאירו את ה-VPN של המערכת:** המנהרה של Connect Beyond Borders פועלת בתוך האפליקציה כתעבורה רגילה ואינה תופסת את מקום ה-VPN של הטלפון שלכם, כך שה-VPN שלכם ממשיך לעבוד לצידה.
- **רעננו נקודות כניסה חסומות:** אם נקודות הכניסה של המעביר של הפרויקט משתנות ומכשיר אינו מצליח להגיע אליהן, ייצאו נקודות כניסה חתומות ממחשב מחובר באמצעות `cbb global entries export` (או `-qr`) וייבאו אותן במחשב המושפע באמצעות `sudo cbb global entries import STRING`.
- **בדקו כשלים:** הריצו `cbb global` במחשב נייד כדי לראות מדוע המנהרה נכשלה, והפעילו `CBB_DEBUG=1` בשירות כדי לצפות ביומני לחיצת היד של WireGuard ([פתרון בעיות: סנכרון מחוץ לבית](troubleshooting.md#sync-away-from-home)).
