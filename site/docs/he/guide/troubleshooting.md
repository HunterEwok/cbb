# פתרון בעיות

למי שהמכשירים שלו לא מסתנכרנים, נכשלים בצימוד או מחזירים שגיאות. כל סעיף שלהלן מפרט את **הסימפטום**, **הסיבה** ו**הפתרון**.

## התחילו באבחון

לפני שמשנים הגדרות, בדקו מה Connect Beyond Borders מדווח:

- **באפליקציית טלפון או שולחן עבודה:** פתחו **הגדרות**, הפעילו **הגדרות מתקדמות**, ובדקו ב**למה אין סנכרון** הסבר במילים פשוטות ואת הצעד הבא. כדי להציג שגיאות טכניות בסיסיות מתחת להודעות קצרות, הקישו על **גרסה** שבע פעמים ב**הגדרות** והפעילו את **הצגת פרטי שגיאות**.
- **במסוף:** הריצו `cbb status` כדי לראות אם השירות פועל, את מצב הקבוצה שלכם, אילו מכשירים מחוברים ואת מצב הסנכרון מחוץ לבית. הוסיפו `CBB_DEBUG=1` לפני כל פקודה (ב-PowerShell ב-Windows, הריצו קודם `$env:CBB_DEBUG = "1"`) כדי להדפיס את השגיאה הבסיסית:

  ```sh
  CBB_DEBUG=1 cbb status
  ```

- **בדקו את יומני השירות:** ב-Linux, הריצו `journalctl -u cbb` עבור השירות ו-`journalctl --user` עבור סוכן הלוח של שולחן העבודה. נתיבי היומנים ל-macOS, ל-Windows, ל-FreeBSD ול-OpenWrt נמצאים ב[מכשירים, יציאות וקבצים](../reference/devices.md#files-and-logs), ומתגי ניפוי השגיאות של כל רכיב נמצאים ב[הודעות שגיאה ופרטיהן](../reference/errors.md).

## פקודות ושירות

### "the Connect Beyond Borders service is not running"

- **הסיבה:** שירות הרקע עצור או נכשל בהפעלה.
- **הפתרון:** הפעילו את השירות עבור מערכת ההפעלה שלכם ובדקו את היומן שלו אם הוא יוצא שוב:
  - **Linux:** `sudo systemctl start cbb` (ללא root: ‏`systemctl --user start cbb`)
  - **macOS:** `sudo launchctl kickstart -k system/tools.cbb`
  - **Windows (PowerShell כמנהל):** `Start-Service cbb`
  - **FreeBSD:** `sudo service cbb start`
  - **OpenWrt:** `/etc/init.d/cbb start`

### "permission denied" בשקע הבקרה אחרי ההתקנה

- **הסיבה:** תוכנית ההתקנה הוסיפה את חשבון המשתמש שלכם לקבוצה `cbb` (‏`_cbb` ב-macOS), וחברות חדשה בקבוצה נכנסת לתוקף רק בהתחברות הבאה שלכם.
- **הפתרון:** התנתקו והתחברו מחדש (ב-Windows, פתחו חלון מסוף חדש). עד שתתחברו מחדש, הריצו פקודות עם `sudo cbb ...`.

## המכשירים לא רואים זה את זה בבית

### `cbb status` מזהיר שמכשירים בבית לא מצליחים להתחבר למחשב הזה

- **הסיבה:** חומת האש של המחשב חוסמת תעבורה נכנסת ב**יציאת TCP 8764** (או יציאת החבר המותאמת שלכם) או ב**יציאת UDP 5353** (‏mDNS).
- **הפתרון:** הריצו שוב את תוכנית ההתקנה וענו `y` לשאלת חומת האש, או הוסיפו את הכללים ידנית באמצעות הפקודות שב[התקנה: חומת האש](install.md#the-firewall).

### `cbb status` אומר "Quiet on" לרשת הביתית שלכם

- **הסיבה:** מחשבים מפרסמים את עצמם ומקבלים חיבורים מקומיים רק ברשתות ביתיות מוכרות. אם החלפתם נתב או שיניתם תת-רשת, המחשב מתייחס לרשת כלא מוכרת.
- **הפתרון:** סמנו את הרשת הנוכחית כרשת ביתית: הריצו `sudo cbb network` במחשב, או לחצו **זו הרשת הביתית שלי** באפליקציית ה-Mac או באפליקציית המגש.

### המכשירים נמצאים בתתי-רשתות או ב-VLAN שונים

- **הסיבה:** גילוי ברשת המקומית (mDNS) אינו חוצה נתבים בין תתי-רשתות נפרדות (לדוגמה, `192.168.0.x` ו-`192.168.20.x`).
- **הפתרון:** חברו את שתי הרשתות דרך רכזת ([מחוץ לבית](away-from-home.md)), הריצו את `cbb` על נתב המחובר לשתי תתי-הרשתות, או העבירו `-peer HOST:PORT` לשירות במכשיר קטן ([מכשירים קטנים](../../member/README.md#install)).

### מכשירים ב-Wi-Fi לא מצליחים להתחבר זה לזה כלל

- **הסיבה:** בנתב מופעלת רשת **Wi-Fi לאורחים** או **בידוד לקוחות / AP**, שמונעת ממכשירים אלחוטיים לתקשר ישירות.
- **הפתרון:** העבירו את המכשירים שלכם לרשת ה-Wi-Fi הביתית הראשית או כבו את בידוד הלקוחות בנתב.

### שני מכשירים מחוברים אבל אף פעם לא מחליפים העתקות

- **הסיבה:** מכשיר אחד נמצא בקבוצה אחרת, **סנכרון** כבוי, או שמנהל השתיק את המכשיר.
- **הפתרון:**
  - בדקו את **סנכרון** בשני המכשירים (`cbb status` או **מסך הבית** באפליקציה) וודאו שאף אחד מהמכשירים אינו מושתק.
  - בדקו את תג הקבוצה ב-`cbb status`. אם מחשב נמצא בקבוצה הלא נכונה, הריצו בו `sudo cbb leave`, צמדו אותו לקבוצה הנכונה, והסירו את הרשומה הישנה שלו מהקבוצה הלא נכונה.

### `cbb status` או האפליקציה אומרים שהמכשיר הזה הוסר מהקבוצה

- **הסיבה:** מנהל הסיר את המכשיר הזה, ולכן כל שאר חברי הקבוצה דוחים את החיבורים שלו.
- **הפתרון:** הריצו `sudo cbb leave` במחשב (או הקישו **עזיבת הקבוצה** באפליקציית הטלפון או שולחן העבודה), ואז צמדו את המכשיר מחדש כמכשיר חדש.

## הצימוד נכשל

### הצימוד מדווח על "wrong code" או שהחלון נסגר

- **הסיבה:** כל חלון צימוד נשאר פתוח 5 דקות ונסגר אוטומטית אחרי 3 ניסיונות שגויים.
- **הפתרון:** פתחו חלון צימוד חדש (`sudo cbb pair` במחשב מנהל, או **+ > הוספת מכשיר** באפליקציה) והזינו את הקוד החדש בן 6 הספרות או סרקו את קוד ה-QR החדש.

### הטלפון לא מצליח להגיע למחשב אחרי סריקת קוד ה-QR

- **הסיבה:** הטלפון והמחשב נמצאים ברשתות שונות, חומת האש של המחשב חוסמת את יציאת TCP 8764, או שהגישה לרשת המקומית ב-iOS נדחתה.
- **הפתרון:**
  1. ודאו ששני המכשירים נמצאים באותה רשת Wi-Fi ביתית או LAN.
  2. ודאו שחומת האש של המחשב מאפשרת את יציאת TCP 8764 ([חומת האש](install.md#the-firewall)).
  3. ב-iPhone, הפעילו **הגדרות > פרטיות ואבטחה > רשת מקומית > CBB**.

## סנכרון מחוץ לבית

### מכשיר מחוץ לבית לא מצליח להתחבר לרכזת

- **הסיבה:** אחת מארבע בעיות נפוצות:
  - הנתב שלכם אינו מעביר את יציאת UDP 8764 אל הרכזת, חומת האש של הרכזת חוסמת אותה, או שהכתובת הציבורית שניתנה ל-`cbb global hub` נמצאת מאחורי carrier-grade NAT.
  - המכשיר שמחוץ לבית לא פגש את הרכזת ברשת הביתית שלכם מאז שהסנכרון מחוץ לבית הופעל או מאז שהרכזת שינתה את הגדרות המנהרה שלה (`-no-obfuscate`,‏ `-no-vless`).
  - כתובת ה-IP הביתית שלכם השתנתה וכלל הרשת היוצא של מערכת המחשב עדיין מאפשר רק את הכתובת הישנה.
  - הרשת שבה אתם מבקרים חוסמת תעבורת WireGuard או UDP.
- **הפתרון:**
  1. הריצו `cbb global` גם במכשיר שמחוץ לבית וגם ברכזת כדי לקרוא את התקלה המדויקת.
  2. אם הבית שלכם מאחורי carrier-grade NAT או שהעברת היציאות נכשלת, העבירו את הרכזת לשימוש במעביר (`sudo cbb global hub` למעביר של הפרויקט; ראו [מחוץ לבית](away-from-home.md#5-when-the-internet-cannot-reach-your-home-a-forwarder)).
  3. אם `cbb global` אומר שכלל הרשת היוצא של המערכת מפגר מאחור, הריצו `sudo cbb global allow` באותו מחשב.
  4. אם המכשיר מעולם לא פגש את הרכזת בבית אחרי שינוי הגדרות, חברו אותו לרשת הביתית שלכם פעם אחת (ופתחו את אפליקציית הטלפון לזמן קצר).
  5. אם הרשת שבה אתם מבקרים מסננת VPN, ודאו ש-AmneziaWG ו-VLESS מופעלים ברכזת ([רשתות שחוסמות VPN](blocked-networks.md)). אם נקודות הכניסה של המעביר של הפרויקט מיושנות, ייבאו נקודות כניסה חתומות עדכניות באמצעות `sudo cbb global entries import STRING`.
  6. כדי לרשום ביומן את לחיצות היד של WireGuard ב-Linux, הגדירו `CBB_DEBUG=1` בשירות והפעילו אותו מחדש:

     ```sh
     sudo systemctl edit cbb
     ```

     הוסיפו את השורות האלה, שמרו והפעילו מחדש:

     ```ini
     [Service]
     Environment=CBB_DEBUG=1
     ```

     ```sh
     sudo systemctl restart cbb
     ```

     אחר כך בדקו את `journalctl -u cbb`.

## טלפונים

### Android: "הגדרה מוגבלת" חוסמת את הפעלת שירות הנגישות

- **הסיבה:** Android 13 ומעלה מגביל הרשאות נגישות לאפליקציות שהותקנו מקובץ APK מחוץ לחנות אפליקציות.
- **הפתרון:** פתחו ב-Android את **הגדרות > אפליקציות > CBB** (פרטי האפליקציה), הקישו על התפריט **⋮** בפינה העליונה, הקישו על **אפשר הגדרות מוגבלות**, ואז הפעילו את **סנכרון הלוח** בהגדרות הנגישות.

### Android: העתקות מהמחשבים מפסיקות להגיע ברקע

- **הסיבה:** מיטוב הסוללה עצר את שירות החזית שפועל ברקע של האפליקציה.
- **הפתרון:** פתחו ב-Android את **הגדרות > אפליקציות > CBB > סוללה** והגדירו אותו ל**ללא הגבלה**.

### iPhone: ‏iOS מבקש הרשאת הדבקה בכל פעם שמסנכרנים

- **הסיבה:** ברירת המחדל של iOS עבור **הדבקה מיישומים אחרים** היא **שאל**.
- **הפתרון:** פתחו ב-iPhone את **הגדרות > יישומים > CBB > הדבקה מיישומים אחרים** ובחרו **אפשר**.

### Aurora OS 5: מפתח המנהל נעול

- **הסיבה:** שבעה ניסיונות שגויים של קוד ה-PIN של המנהל נועלים לצמיתות את מפתח המנהל ברכיב המאובטח של הטלפון. הטלפון נשאר בקבוצה כחבר רגיל.
- **הפתרון:** עזבו את הקבוצה, התקינו מחדש את **CBB**, והצטרפו שוב כמכשיר חדש.
