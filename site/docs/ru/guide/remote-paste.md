# Удалённая вставка

Для всех, кто хочет вставить текст, изображения или файлы с телефона или компьютера-администратора
прямо в активное приложение на другом компьютере — например, пароль в поле входа, команду в терминал
или снимок экрана в чат.

Администратор подписывает запрос на вставку, а целевой компьютер помещает содержимое туда, где
находится фокус клавиатуры, вставляя целиком или набирая по клавишам. Удалённая вставка выключена на
каждом компьютере, пока его собственный пользователь не включит её локально; никто не может включить
её на расстоянии. Телефоны отправляют удалённые вставки на компьютеры и сами их не принимают.

## 1. Включите удалённую вставку на целевом компьютере

Выполните настройку для операционной системы целевого компьютера:

| Целевая система | Шаги настройки | Куда попадают вставки |
|---|---|---|
| **Linux** | Выполните `sudo cbb paste-receive on` | Активное приложение на рабочем столе (X11, Wayland, GNOME, KDE), активная панель `tmux` и (с `-console`) текстовая консоль Linux |
| **FreeBSD** | Выполните `sudo cbb paste-receive on` | Активное приложение в X11 и композиторах Wayland на wlroots (например, sway и Hyprland); GNOME во FreeBSD не поддерживается, поскольку недоступно состояние блокировки экрана |
| **Windows** | Откройте терминал от имени администратора и выполните `cbb paste-receive on` | Активное окно |
| **macOS** | Выполните `sudo cbb paste-receive on`, держите открытым приложение **CBB** в строке меню и разрешите ему доступ в разделе **Системные настройки → Конфиденциальность и безопасность → Универсальный доступ** | Активное приложение |
| **Небольшое устройство с Linux без рабочего стола** | Выполните `sudo cbb paste-receive on` (добавьте `-console` для текстовой консоли Linux) | Активная панель `tmux` или текстовая консоль |

Необязательные флаги для `cbb paste-receive on`:

- `-enter`: Разрешает удалённой вставке нажимать Enter после содержимого. Без `-enter` любой текст с
  переводом строки отклоняется, чтобы вставка не могла случайно выполнить команду в терминале.
- `-console`: Разрешает удалённую вставку в текстовую консоль Linux и сеансы `tmux` пользователя
  `root` (недоступно для установок без прав root).
- `-no-lock-check`: В Linux и FreeBSD без `logind` разрешает удалённую вставку, когда система не
  может сообщить состояние блокировки сеанса (запущенный блокировщик экрана всё равно блокирует
  вставки).

**Результат:** Выполните `cbb paste-receive` без аргументов, чтобы убедиться, что удалённая вставка
включена, и посмотреть активные параметры.

### Дополнительные помощники в Linux

- **Системные окна GNOME и KDE:** Первая удалённая вставка открывает системное окно подтверждения
  удалённого управления рабочего стола; разрешите его один раз, чтобы рабочий стол это запомнил.
  Чтобы пропустить это окно (и разрешить ввод клавиш на рабочих столах без другого способа ввода),
  переустановите программу с флагом `--uinput`:

  ```sh
  curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sudo sh -s -- --uinput
  ```

  Это добавит `cbb-uinput.service` — виртуальную клавиатуру, которая нажимает только Shift+Insert и
  Enter для вошедшего пользователя.
- **Серверный `tmux` и текстовые консоли:** Каждая установка в Linux добавляет перехватчик Connect
  Beyond Borders в `/etc/tmux.conf`, чтобы `tmux` автоматически запускал помощника вставки. Для
  текстовой консоли Linux выполните установку с флагом `--console` (см.
  [Установка на Linux](install.md#linux)).

## 2. Отправьте удалённую вставку от имени администратора

### С компьютера-администратора

Выполните `cbb paste -on DEVICE` в терминале (`DEVICE` — имя целевого устройства или его ID из
`cbb status`):

```sh
echo 'the text' | cbb paste -on DEVICE              # paste text from standard input
cbb paste -on DEVICE                                # paste this computer's clipboard text
cbb paste -on DEVICE -type < note.txt               # type text key by key (up to 4 KiB)
cbb paste -on DEVICE -enter -secret < pass.txt      # paste as a secret and press Enter
cbb paste -on DEVICE photo.jpg notes/               # paste files into the focused app
cbb paste -on DEVICE -image screenshot.png          # paste a PNG or JPEG as an image
cbb paste -on DEVICE -copy                          # paste the group's current image or files
```

**Результат:** Команда выведет `Pasted on DEVICE.`, когда целевое устройство примет и выполнит
вставку, или сообщит точную причину отказа.

### С телефона-администратора

1. Откройте **CBB**, нажмите на целевой компьютер на главном экране и выберите **Вставить на нём…**.
2. Выберите, что отправить:
   - **Текст:** Введите текст (или оставьте поле пустым, чтобы отправить содержимое буфера обмена
     телефона), при желании выберите набор по клавишам, **Секрет** или **Нажать Enter после него**
     и нажмите **Вставить**.
   - **Изображения или файлы:** Нажмите **Вставить картинку или файлы…** (на iPhone — **Вставить
     картинку…** или **Вставить файлы…**) и выберите объекты.
3. Подтвердите действие лицом, отпечатком пальца, код-паролем или (на ОС Аврора) вашим PIN
   администратора.

На iPhone выберите **Настройки → Приложения → CBB → Вставка из других приложений → Разрешить**,
чтобы iOS не спрашивала каждый раз, когда приложение читает буфер обмена.

**Результат:** Целевой компьютер вставит или наберёт содержимое в активном окне, а приложение
покажет **Вставлено.**

### Вставка и набор по клавишам

- **Вставка** работает в большинстве приложений для рабочего стола и поддерживает текст (до 1 МиБ),
  изображения и файлы.
- **Набор по клавишам** (`-type`) отправляет нажатия клавиш по одному (только текст, до 4 КиБ) для
  приложений, которые блокируют вставку из буфера обмена. Набор работает независимо от раскладки
  клавиатуры в X11, композиторах Wayland с протоколом виртуальной клавиатуры, Windows и macOS. В
  GNOME и KDE через системное окно удалённого управления работает вставка, а набор недоступен.

## Когда целевой компьютер отклоняет вставку

Целевой компьютер отклоняет удалённую вставку, когда:

- Его экран заблокирован, активна заставка или показан экран входа.
- В Windows активное окно запущено от имени администратора или открыт запрос повышения прав
  администратора.
- В macOS фокус клавиатуры находится в поле пароля или включён безопасный ввод с клавиатуры (Secure
  Keyboard Entry).
- Никто не подключён к `tmux` или не вошёл в текстовую консоль (на устройствах без рабочего стола).
- Текст содержит перевод строки, а на целевом компьютере не включён `-enter`.
- Один отправитель превышает ограничение частоты: **1 вставка в секунду** или **30 вставок в
  минуту**.

В ошибке, возвращаемой отправителю, указывается причина.

## Безопасность и выключение удалённой вставки

- **Ограничивайте список администраторов:** Любой администратор вашей группы может вводить текст на
  компьютере, пока на нём включена удалённая вставка. Включайте её только на тех компьютерах, где
  она нужна, и держите список администраторов коротким.
- **Журнал аудита вставок:** Каждое целевое устройство записывает последние 100 запросов вставки
  (отправитель, время, длина, способ и результат — но никогда не вставленный текст). Секреты после
  вставки не оставляют следов в буфере обмена целевого компьютера.
- **Выключение локально:** Выполните `sudo cbb paste-receive off` на целевом компьютере (выключение
  также сбрасывает `-enter`, `-console` и `-no-lock-check`).
- **Выключение удалённо с любого администратора:** Выполните `sudo cbb paste-receive off -on DEVICE`
  (или `-all`, чтобы выключить удалённую вставку на всех компьютерах группы). Включить её обратно
  сможет только пользователь каждого компьютера.

Точные ограничения размера и частоты см. в разделе
[Ограничения и сроки](../reference/limits.md#remote-paste-and-quick-actions). Как удалённая вставка
устроена внутри, см. в разделе [Архитектура: удалённая вставка](../design.md#remote-paste).
