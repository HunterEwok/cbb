# Установка

Для всех, кто устанавливает, обновляет, проверяет или удаляет Connect Beyond Borders на компьютере,
роутере или домашнем сервере. О приложениях для телефонов, планшетов, часов и телевизоров читайте в
разделе [Приложения](apps.md).

Connect Beyond Borders работает как небольшая фоновая служба на каждом компьютере. Его инструмент
командной строки называется `cbb`. Все способы ниже ставят одну и ту же службу — выберите тот, что
подходит вашей системе.

## Linux

Поддерживается на системах Linux с `systemd` на архитектурах x86-64, ARM64, ARMv7 и ARMv6 (ноутбуки,
настольные компьютеры, платы Raspberry Pi, серверы и Steam Deck).

1. Запустите установщик в терминале:

   ```sh
   curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sudo sh
   ```

2. Ответьте на вопросы о правилах файрвола (если найден активный файрвол) и о ежедневных
   автоматических обновлениях.
3. Один раз выйдите из системы и войдите снова, чтобы ваша учётная запись (добавленная в группу `cbb`)
   могла запускать `cbb` без `sudo`.

На рабочих столах x86-64 и ARM64 с установленными GTK 4 и WebKitGTK 6.0 (`libgtk-4-1
libwebkitgtk-6.0-4` в Debian и Ubuntu; `gtk4 webkitgtk6.0` в Fedora) установщик также ставит
приложение в трее (`cbb-desktop`), которое запускается вместе с сеансом рабочего стола и появляется в
меню приложений. Если этих библиотек нет, установщик назовёт нужные пакеты; после их установки
запустите установщик снова, чтобы установить приложение в трее.

Установщику `get.sh` можно передать дополнительные параметры после `sh -s --`:

- **Текстовая консоль (`--console`):** для машины без рабочего стола — добавляет копирование и вставку
  внутри `tmux` и устанавливает `cbb-console.service` для удалённой вставки в текстовой консоли:

  ```sh
  curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sudo sh -s -- --console
  ```

- **Без системных запросов при вставке на рабочем столе (`--uinput`):** в GNOME и KDE удалённая
  вставка один раз спрашивает в системном окне перед тем, как нажимать клавиши. Параметр `--uinput`
  устанавливает `cbb-uinput.service` и загружает модуль ядра `uinput`, чтобы Connect Beyond Borders
  нажимал клавиши вставки напрямую (никогда не на экране входа или блокировки). Для этого параметра
  требуется `cbb-helper`.
- **Малые устройства без помощника (`--no-helper`):** не устанавливает `cbb-helper` (вспомогательную
  программу для ключей TPM, буфера обмена рабочего стола, ввода клавиш при удалённой вставке,
  Bluetooth-клавиатур и пультов телевизора) на малых устройствах, которые только синхронизируются:

  ```sh
  curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sudo sh -s -- --no-helper
  ```

  См. [Малые устройства](../../member/README.md). Архивы для роутеров MIPS изначально идут без
  `cbb-helper`. Если устройство установлено без `cbb-helper`, последующие обновления сохраняют такой
  вид установки.

Поддерживается и Homebrew в Linux (x86-64 и ARM64):

```sh
brew install hunterewok/tap/cbb
sudo sh "$(brew --prefix)/opt/cbb/share/cbb/packaging/linux/install.sh" "$(brew --prefix)/opt/cbb/bin/cbb"
```

После каждого `brew upgrade` выполняйте вторую команду заново.

### Без sudo (rootless)

На компьютере с Linux, где у вас нет прав администратора (`sudo`), установите Connect Beyond Borders
для своей учётной записи без `sudo`:

```sh
curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sh -s -- --rootless
```

Это устанавливает `cbb` в `~/.local/bin` и запускает его как пользовательскую службу `systemd`, пока
вы находитесь в системе. Такую установку нельзя совмещать с общесистемной.

Используйте установку без прав root, только когда обычная установка невозможна. Поскольку любая
программа, запущенная под вашей учётной записью, может прочитать его файлы ключей, устройство без прав
root никогда не может быть **главным устройством**, **администратором** или **хабом**
([участники без прав root](how-it-works.md#rootless-members)). При установке без прав root также нет
правил файрвола, поддержки TPM и помощников `--console` или `--uinput`.

- **Продолжать работу после выхода из системы:** если установщик не смог автоматически включить режим
  lingering, попросите администратора один раз выполнить `sudo loginctl enable-linger YOUR-USER`.
- **Без помощника:** передайте `--no-helper --rootless`, чтобы не ставить и `cbb-helper` (см.
  [без sudo на малых устройствах](../../member/README.md#without-sudo-rootless)).
- **Удаление:** выполните `sh ~/.local/share/cbb/uninstall.sh`.

### SteamOS (Steam Deck)

1. Переключитесь в **Режим рабочего стола** и откройте **Konsole**.
2. Если вы ещё не задали пароль для пользователя `deck`, выполните `passwd`, чтобы задать его.
3. Выполните команду установки для Linux:

   ```sh
   curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sudo sh
   ```

SteamOS заменяет корневую файловую систему при каждом обновлении ОС, поэтому установщик размещает
Connect Beyond Borders в `/opt/cbb` вместо `/usr/local` и регистрирует его файлы конфигурации из
`/etc` в `/etc/atomic-update.conf.d/cbb.conf`. Ваша установка и участие в группе сохраняются после
обновлений SteamOS.

- После выхода из системы и повторного входа `cbb` появится в `PATH` в Konsole. Поскольку `sudo` не
  ищет в `/opt/cbb/bin`, для команд, требующих `sudo`, нужно указывать полный путь, например
  `sudo /opt/cbb/bin/cbb pair -code`.
- В режиме рабочего стола буфер обмена синхронизируется как на любом рабочем столе KDE Plasma.
- В игровом режиме нет буфера обмена рабочего стола, поэтому там ничего не синхронизируется; служба
  продолжает работать и догоняет изменения, когда вы возвращаетесь в режим рабочего стола.
- Чтобы удалить программу, выполните `sudo sh /opt/cbb/share/uninstall.sh`.

## Mac

Поддерживается на Mac с чипом Apple и Intel под управлением macOS 14 или новее.

- **Пакет установщика (рекомендуется, включает приложение в строке меню):** скачайте `cbb-X.Y.Z.pkg`
  со страницы [последнего релиза на GitHub](https://github.com/HunterEwok/cbb/releases/latest) и
  откройте его. Пакет устанавливает приложение **CBB** в строке меню (`/Applications/CBB.app`) и
  фоновую службу — оба подписаны и заверены Apple.
- **Терминал (только служба и `cbb`, без приложения в строке меню):**

  ```sh
  curl -fsSL https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sudo sh
  ```

- **Homebrew (только служба и `cbb`, без приложения в строке меню):**

  ```sh
  brew install hunterewok/tap/cbb
  sudo sh "$(brew --prefix)/opt/cbb/share/cbb/packaging/macos/install.sh" --in-place "$(brew --prefix)/opt/cbb/bin/cbb"
  ```

  Выполняйте вторую команду заново после каждого `brew upgrade`, чтобы перезапустить службу и агент
  буфера обмена на новой версии.

## Windows

Поддерживается на Windows 10 (версии 1809 или новее) и Windows 11, на архитектурах x86-64 и ARM64.

1. Откройте PowerShell через **Запуск от имени администратора**.
2. Запустите установщик:

   ```powershell
   irm https://github.com/HunterEwok/cbb/releases/latest/download/get.ps1 | iex
   ```

3. Ответьте на вопросы о правилах Брандмауэра Windows и о ежедневных автоматических обновлениях.
4. Откройте новое окно терминала, чтобы пользоваться `cbb`.

Установщик добавляет вошедшего пользователя в группу `cbb`, запускает фоновую службу и агент буфера
обмена, а также устанавливает приложение в трее (запускается при входе в систему и отображается в меню
«Пуск» как **CBB**). Команды, меняющие состав группы или настройки, выполняются в терминале от имени
администратора — там, где в Linux и macOS используется `sudo`.

Для установки через **winget** (используется пакет `HunterEwok.cbb`):

```powershell
winget install HunterEwok.cbb
cbb install
```

Выполните `cbb install` в терминале от имени администратора, чтобы установить службу, агент буфера
обмена, приложение в трее и правила файрвола из распакованного пакета, и запускайте её заново после
каждого `winget upgrade`.

## OpenWrt

Поддерживается на роутерах с OpenWrt 25.12 или новее (с пакетным менеджером `apk`) и местом для
программы размером 25 МБ (не менее 128 МБ флеш-памяти или eMMC и 256 МБ ОЗУ).

Подключитесь по SSH как `root` и выполните:

```sh
uclient-fetch -qO - https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sh
```

Установщик настраивает `cbb` (без `cbb-helper`) как службу `procd`, которая слушает только в зоне
`lan` и никогда не отвечает в `wan`. Ключи хранятся в `/etc/cbb/state`, который сохраняется при
`sysupgrade`; после управляемого обновления sysupgrade (ASU или `owut`) выполните команду установки
снова. При запуске в интерактивном терминале установщик сразу начинает сопряжение (`--no-pair`
пропускает этот шаг). Дополнительные зоны (например, сеть IoT), подробности о файрволе и проверки
описаны в разделе [Роутеры и FreeBSD](../admin/routers.md#openwrt).

Можно также установить из ленты пакетов `apk` проекта, чтобы `apk upgrade` поддерживал программу в
актуальном состоянии:

1. Узнайте архитектуру роутера командой `grep DISTRIB_ARCH /etc/openwrt_release` и сопоставьте её с
   каталогом ленты:
   - `aarch64_*` → `arm64`
   - `arm_cortex-a*` (с `neon` или `vfp` в названии) → `armv7`
   - `mipsel_*` → `mipsle`
   - `mips_*` → `mips`
   - `x86_64` → `amd64`
2. Добавьте ключ ленты и репозиторий (замените `arm64` на вашу архитектуру) и установите пакет:

   ```sh
   uclient-fetch -qO /etc/apk/keys/cbb.pem https://cbb.tools/openwrt/cbb.pem
   echo https://cbb.tools/openwrt/arm64/packages.adb >>/etc/apk/repositories.d/customfeeds.list
   apk update && apk add cbb
   ```

`apk del cbb` удаляет пакет и сохраняет ключи в `/etc/cbb`. Учтите, что сборки для роутеров `mips` и
`mipsle` синхронизируются только в домашней сети (без синхронизации вне дома).

## FreeBSD

Поддерживается на FreeBSD 15 (`amd64` и `arm64`). Выполните от имени `root` (через `sudo` или `doas`):

```sh
fetch -qo - https://github.com/HunterEwok/cbb/releases/latest/download/get.sh | sh
```

Установщик устанавливает `cbb`, добавляет сценарий `rc.d`, который запускает службу через `daemon(8)`,
и добавляет строку `cbb_enable="YES"` в `rc.conf`. Ключи хранятся в `/var/db/cbb`, а настройки — в
`/usr/local/etc/cbb`.

- **OPNsense:** тот же установщик добавляет хук плагина, чтобы служба появлялась в разделе
  **System > Diagnostics > Services**, а её правила файрвола (в якоре `pf` с именем `cbb`) сохранялись
  при перезагрузках фильтра. Выключите **Services > mDNS Repeater**, пока работает Connect Beyond
  Borders, потому что обоим нужен UDP-порт 5353, а служба сама отвечает на mDNS на каждом домашнем
  интерфейсе.
- **pfSense (не поддерживается):** установщик запускается на pfSense, выводит правила, которые нужно
  добавить вручную в **Firewall > Rules**, и может быть удалён при обновлении системы pfSense.
- **Рабочие столы FreeBSD:** в X11 или в композиторах Wayland с протоколом data-control (таких как
  KDE, sway и Hyprland) автозапуск XDG запускает `cbb agent` при повторном входе в систему. Удалённая
  вставка использует XTEST в X11 и виртуальную клавиатуру в рабочих столах wlroots; GNOME во FreeBSD
  не принимает удалённую вставку, поскольку без `logind` недоступен статус блокировки экрана.

## Docker

Для NAS или постоянно включённого домашнего сервера без рабочего стола (см.
[README образа Docker](../../packaging/docker/README.md)). Контейнер вступает в группу как обычный
участник; группу создайте на телефоне или на компьютере, которым вы владеете.

```sh
curl -fsSLO https://raw.githubusercontent.com/HunterEwok/cbb/main/packaging/docker/compose.home.yaml
docker compose -f compose.home.yaml up -d
docker compose -f compose.home.yaml exec cbb cbb pair -code
```

Сначала откройте окно сопряжения на телефоне или на компьютере-администраторе, а затем введите шесть
цифр, когда `cbb pair -code` запросит их.

## Файрвол

Connect Beyond Borders требуются входящий **TCP-порт 8764** (или выбранный вами порт участника) и
**UDP-порт 5353** (mDNS) — только из вашей домашней сети.

Установщик определяет ваш файрвол (`ufw`, `firewalld`, `nftables` или `iptables` в Linux; `pf`, `ipfw`
или OPNsense во FreeBSD; файрвол приложений macOS; Брандмауэр Windows), перечисляет все необходимые
правила и спрашивает `Add these rules now? [y/N]` (`Add this rule now? [y/N]` на macOS):

- **Да:** установщик добавляет правила, поддерживает их в актуальном состоянии при обновлениях и
  удаляет при удалении программы, не затрагивая остальные правила.
- **Нет** (по умолчанию, а также если нет интерактивного терминала): установщик не добавляет правил и
  выводит точные команды, чтобы вы выполнили их сами.
- **Параметры для автоматической установки:**
  - В Linux, macOS и FreeBSD: передайте `--express`, чтобы добавить правила без вопроса, или
    `--no-firewall`, чтобы отказаться и вывести команды.
  - В Windows: задайте `$env:CBB_FIREWALL = "express"` или `$env:CBB_FIREWALL = "no"` перед запуском
    `get.ps1` (или передайте `-Express` либо `-NoFirewall` в `install.ps1`).

Особенности отдельных файрволов:

- `nftables` и `iptables` всегда только выводят команды для ручного выполнения, потому что правила,
  добавленные во время работы, не сохраняются после перезагрузки.
- `pf` во FreeBSD размещает правила в собственном якоре `cbb`, который загружается через три
  помеченные строки в конце `/etc/pf.conf` (удаляются при удалении программы). `ipfw` во FreeBSD
  добавляет их в набор правил 17 и загружает заново при каждом запуске.
- Если вы включите файрвол уже после установки Connect Beyond Borders, запустите установщик снова.

Чтобы выбрать другой порт участника, если TCP 8764 уже занят:

- В Linux, macOS, FreeBSD и OpenWrt: передайте `--port 9000` (например,
  `... | sudo sh -s -- --port 9000`).
- В Windows: задайте `$env:CBB_PORT = "9000"` перед запуском `get.ps1` (или передайте `-Port 9000` в
  `install.ps1`).

Все параметры установщика перечислены в [справочнике команд](../reference/cli.md#installers).

## Обновление

Держите все устройства группы на одном релизе. Подробности о совместимости см. в разделе
[Версии и совместимость](../reference/compatibility.md).

### Ручное обновление

- **Установка через `get.sh`, `get.ps1` или архив релиза:**
  - Проверить наличие новой версии: `cbb update -check`
  - Установить новейший подписанный релиз: `sudo cbb update` (в Windows выполните `cbb update` в
    терминале от имени администратора; в Linux без прав root выполните `cbb update` без `sudo`; в
    SteamOS выполните `sudo /opt/cbb/bin/cbb update`).

  `cbb update` сохраняет настройки и ключи, устанавливает только релизы, подписанные проектом,
  отказывается от более старых версий и автоматически возвращает предыдущую версию, если обновлённая
  служба не запустилась в течение одной минуты. Повторный запуск исходной команды `get.sh` или
  `get.ps1` тоже обновляет программу.
- **Homebrew:** выполните `brew upgrade cbb`, а затем повторите команду `install.sh` из раздела
  [Mac](#mac) или [Linux](#linux).
- **winget:** выполните `winget upgrade HunterEwok.cbb`, а затем запустите `cbb install` в терминале
  от имени администратора.
- **Docker:** выполните `docker compose -f compose.home.yaml pull` и пересоздайте контейнер.
- **Лента пакетов OpenWrt:** выполните `apk update && apk upgrade`.

### Автоматические обновления

При установке через `get.sh` и `get.ps1` установщик один раз спрашивает, включить ли ежедневные
автоматические обновления. Вы можете заранее задать ответ или изменить настройку позже:

- **Во время установки:** передайте `--auto-update on` или `--auto-update off` в `get.sh`; в Windows
  задайте `$env:CBB_AUTO_UPDATE = "on"` или `"off"` перед запуском `get.ps1` (или передайте
  `-AutoUpdate on|off` в `install.ps1`).
- **После установки:** выполните `sudo cbb update -auto on` или `sudo cbb update -auto off` (без
  `sudo` в Linux без прав root; в терминале от имени администратора в Windows).

Когда автоматические обновления включены, ежедневное расписание проверяет подписанные релизы: таймер
`systemd` в Linux (пользовательский таймер при установке без прав root), задание `launchd` на macOS,
запланированная задача от имени `SYSTEM` в Windows или `cron` в OpenWrt и FreeBSD.

При каждой проверке загружаются небольшие подписанные файлы метаданных с GitHub (или с `dl.cbb.tools`,
если GitHub не отвечает). GitHub видит IP-адрес устройства и то, что оно запрашивает метаданные
Connect Beyond Borders, но ничего о вашей группе. Чтобы использовать собственное зеркало, выполните
`sudo cbb update -mirror https://...`; зеркалу не нужно доверять, так как подписи всё равно
проверяются.

Журналы автоматических обновлений записываются в файл `update.log` в каталоге:

| Система | Каталог журнала обновлений |
|---|---|
| Linux | `/var/lib/cbb-update` |
| Linux (без прав root) | `~/.local/state/cbb-update` |
| SteamOS | `/opt/cbb-update` |
| OpenWrt | `/etc/cbb-update` |
| FreeBSD | `/var/db/cbb-update` |
| macOS | `/Library/Application Support/cbb-update` |
| Windows | `C:\Program Files\cbb-update` |

Устройства группы обмениваются уведомлениями о новейшем подписанном релизе, который видело любое из
них, поэтому `cbb status` и приложения для компьютеров сообщат вам, когда выйдет обновление. При этом
каждое устройство само проверяет подписи и скачивает собственный архив.

## Проверка загрузки

Каждый архив релиза проверяется тремя способами:

1. **Контрольные суммы (`SHA256SUMS`):** и `get.sh`, и `get.ps1` сверяют скачанный архив с файлом
   `SHA256SUMS` релиза.
2. **Подписи релизов проекта:** релизы подписываются автономными корневыми ключами проекта и ключом
   релиза (которые никогда не попадают в CI): `keys.json` заверяет ключи релиза под корневыми ключами
   проекта, `release.json` перечисляет размер и хеш SHA-256 каждого файла, а `stable.json` называет
   текущий стабильный релиз ([Протокол](../protocol.md), раздел 16). И `get.sh` (через `openssl`), и
   `get.ps1` содержат встроенные корневые ключи проекта и отказываются устанавливать любой релиз, чьи
   подписи не прошли проверку. `get.sh` проверяет обе подписи ES256 и SLH-DSA-SHA2-128s при наличии
   OpenSSL 3.5 или новее (и ES256 на более старом OpenSSL); `get.ps1` проверяет ES256. Чтобы
   установить без проверки подписей проекта, задайте `CBB_VERIFY=skip`.
3. **Аттестация происхождения сборки:** у каждого файла релиза есть аттестация происхождения сборки
   GitHub, связывающая его с рабочим процессом релиза этого репозитория. С помощью
   [GitHub CLI](https://cli.github.com/) (`gh`) можно вручную проверить любой файл:

   ```sh
   gh attestation verify cbb-linux-amd64.tar.gz --repo HunterEwok/cbb
   ```

   И `get.sh`, и `get.ps1` выполняют эту проверку автоматически, когда `gh` установлен и выполнен вход
   (`gh auth login`; для `get.sh` под `sudo` выполните `sudo gh auth login`). Задайте
   `CBB_ATTESTATION=require`, чтобы отказаться от установки без проверенной аттестации, или
   `CBB_ATTESTATION=skip`, чтобы пропустить проверку аттестации.

## Удаление

Выполните команду удаления для вашей системы:

| Система | Команда или шаги |
|---|---|
| Linux и macOS | `sudo sh /usr/local/share/cbb/uninstall.sh` |
| Linux (без прав root) | `sh ~/.local/share/cbb/uninstall.sh` |
| SteamOS | `sudo sh /opt/cbb/share/uninstall.sh` |
| FreeBSD | `sudo sh /usr/local/share/cbb/uninstall.sh` (или с `doas`) |
| OpenWrt | `sh /usr/share/cbb/uninstall.sh` (или `apk del cbb`, если установка была из ленты) |
| Windows | Откройте **Параметры > Приложения > CBB > Удалить** или выполните `powershell -ExecutionPolicy Bypass -File "$env:ProgramFiles\cbb\uninstall.ps1"` от имени администратора |

Если вы устанавливали программу через Homebrew, сначала запустите скрипт удаления, а затем выполните
`brew uninstall cbb`.

Удаление убирает программу, фоновую службу, агент буфера обмена, таймер обновлений, правила файрвола,
добавленные установщиком, и (на macOS) `/Applications/CBB.app`, если оно было установлено из `.pkg`.
Ключи устройства и состояние группы остаются на диске, чтобы при повторной установке устройство
вернулось в ту же группу.

- **Удалить также ключи и состояние группы:** добавьте `--purge` в Unix-системах или выполните
  `uninstall.ps1 -Purge` в PowerShell от имени администратора в Windows. После этого удалите
  устройство из группы на устройстве-администраторе (`sudo cbb remove NAME` или в приложении на
  телефоне).
- **Выйти из группы без удаления программы:** выполните `sudo cbb leave` (без `sudo` в Linux без прав
  root или `cbb leave` в терминале от имени администратора в Windows). Это удалит ключи устройства и
  файлы группы, но оставит Connect Beyond Borders установленным, чтобы устройство могло снова вступить
  в группу.
