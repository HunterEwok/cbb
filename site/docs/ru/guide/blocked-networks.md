# Сети, блокирующие VPN

Для всех, кто синхронизируется вне дома в сетях, фильтрующих или блокирующих WireGuard: в Wi-Fi
гостиниц, офисных сетях, у мобильных операторов или в странах со строгой фильтрацией трафика. На
этой странице вы узнаете, как проверить или изменить способ маскировки туннеля вашего хаба.

Вне дома ваши устройства подключаются к хабу через собственный туннель WireGuard группы. По
умолчанию хаб использует и **AmneziaWG**, и (при работе с сервером пересылки, поддерживающим
VLESS) **VLESS**, чтобы туннель проходил через фильтрующие сети. Независимо от способа маскировки,
ваши копии остаются внутри WireGuard, взаимного TLS 1.3 и сквозного шифрования; см.
[Как это работает](how-it-works.md#networks-that-block-vpns).

| Транспорт | Что видит сеть | Требования | Поддерживаемые устройства |
|---|---|---|---|
| **AmneziaWG** (включён по умолчанию) | UDP-пакеты со случайными заголовками и заполнением | Хаб или сервер пересылки | Компьютеры, небольшие устройства (кроме роутеров на MIPS), телефоны |
| **VLESS** (включён по умолчанию с сервером пересылки с VLESS) | HTTPS-соединение с сайтом сервера пересылки | Сервер пересылки с включённым VLESS (у сервера пересылки проекта на `cbb.tools` он есть) | Компьютеры, небольшие устройства (кроме роутеров на MIPS), телефоны |
| **Обычный WireGuard** (`-no-obfuscate -no-vless`) | Обычные UDP-пакеты WireGuard | Хаб или сервер пересылки | Компьютеры, небольшие устройства (кроме роутеров на MIPS), телефоны |

## Как выбирают устройства

Когда хаб работает с сервером пересылки, поддерживающим VLESS, устройства вне дома сначала пробуют
**AmneziaWG** по UDP, потому что UDP быстрее там, где сеть его пропускает. Если UDP заблокирован —
как в сетях, которые пропускают только веб-трафик, — они автоматически переключаются на **VLESS**
поверх HTTPS (TCP-порт 443) к серверу пересылки и остаются на том транспорте, который сработал.

Когда VLESS включён, устройства никогда не откатываются на обычный WireGuard, поэтому фильтрующие
сети не видят незамаскированный VPN-трафик. Хаб без сервера пересылки предлагает только AmneziaWG.

Никакая маскировка туннеля не поможет в сети, которая разрешает подключения только к фиксированному
списку одобренных IP-адресов или доменов.

## Настройка маскировки туннеля в приложении для компьютера

На хабе, где запущено приложение для Mac или приложение в трее для Linux и Windows:

1. Откройте **CBB** и выберите страницу этого компьютера.
2. В разделе **Строгие сети** переключите:
   - **Сети, которые блокируют VPN (AmneziaWG)** — чтобы включить или выключить AmneziaWG.
   - **Сети, где открыт только веб (VLESS)** — чтобы включить или выключить VLESS (требуется
     сервер пересылки с поддержкой VLESS).
3. Подтвердите действие паролем администратора, Touch ID, Windows Hello или запросом polkit.
4. Один раз подключите каждый ноутбук и телефон к домашней сети, чтобы они получили обновлённые
   настройки туннеля хаба.

**Результат:** Хаб сохранит обновлённые настройки и передаст их вашим устройствам при следующей
встрече дома.

## AmneziaWG

Каждый хаб включает AmneziaWG по умолчанию сразу после настройки:

```sh
sudo cbb global hub 203.0.113.7:8764
```

Хаб создаёт случайные параметры AmneziaWG для вашей группы и автоматически обновляет их с каждым
периодом серверных учётных данных (примерно раз в месяц), заранее передавая следующий набор.

Чтобы переключиться на обычный WireGuard в сетях, где ничего не блокирует VPN (это уменьшает
накладные расходы на пакеты):

1. Выполните на хабе (флаг `-keep` сохраняет текущие адреса хаба и сервер пересылки):

   ```sh
   sudo cbb global hub -keep -no-obfuscate -no-vless
   ```

2. Один раз подключите каждый ноутбук и телефон, используемый вне дома, к домашней сети (и ненадолго
   откройте приложение на телефоне), чтобы устройство получило новые настройки.

**Результат:** Ваши устройства перейдут на обычный WireGuard, как только получат обновлённое
предложение дома.

## VLESS

VLESS передаёт ваш замаскированный под AmneziaWG туннель внутри соединения, которое для сети
выглядит как обычное HTTPS-соединение с сайтом сервера пересылки. Использование AmneziaWG внутри
VLESS скрывает размеры пакетов WireGuard, которые иначе могли бы выделяться внутри HTTPS.

1. **Выберите сервер пересылки с VLESS:**
   - **У сервера пересылки проекта на `cbb.tools`** VLESS уже включён; для сети ваши устройства
     выглядят так, будто заходят на `cbb.tools`.
   - **Ваш собственный сервер пересылки:** Запустите `cbb forward` за веб-сервером, у которого есть
     TLS-сертификат вашего сайта:

     ```sh
     cbb forward -vless-xhttp vpn.example.org
     ```

     Настройте веб-сервер так, чтобы он проксировал путь, который выводит `cbb forward`, на
     локальный адрес прослушивания сервера пересылки (по умолчанию `127.0.0.1:3276`), а всем
     остальным отдавал страницы вашего сайта. Откройте **TCP-порт 443** в файрволе сервера наряду с
     UDP- и TCP-портом 8764. См.
     [Свои серверы: VLESS на сервере пересылки](../admin/self-hosting.md#vless-on-the-forwarder).

2. **Укажите хабу сервер пересылки:** На хабе зарегистрируйтесь на сервере пересылки проекта или на
   своём собственном:

   ```sh
   sudo cbb global hub -forwarder default
   ```

   Для собственного сервера пересылки вместо этого передайте его адрес и ключ:

   ```sh
   sudo cbb global hub -forwarder 198.51.100.9:8764 -forwarder-key KEY
   ```

   **Результат:** Хаб автоматически запросит VLESS. Если сервер пересылки поддерживает VLESS, он
   передаст хабу имя своего сайта и путь; иначе хаб зарегистрируется только для UDP. Чтобы выключить
   VLESS, сохранив AmneziaWG, передайте `-no-vless` (например,
   `sudo cbb global hub -keep -no-vless`).

3. **Один раз синхронизируйтесь дома:** Подключите каждый ноутбук и телефон к домашней сети (и
   ненадолго откройте приложение на телефоне) после изменения настроек хаба.

   **Результат:** Ваши устройства получат предложение VLESS от хаба и будут автоматически
   использовать его всегда, когда UDP заблокирован.

## Советы для стран с фильтрацией трафика

- **Настройте и проверьте всё дома до поездки.** Устройства получают настройки туннеля хаба только
  в домашней сети.
- **Разместите сервер пересылки за пределами фильтрующей страны** у провайдера, чьи IP-адреса там
  не заблокированы.
- **Учитывайте блокировку доменов:** Доменное имя сервера пересылки видно при TLS-рукопожатии (SNI).
  Если сеть блокирует `cbb.tools`, запустите свой сервер пересылки за другим доменным именем.
- **Оставьте свой системный VPN:** Туннель Connect Beyond Borders работает внутри приложения как
  обычный трафик и не занимает слот VPN в телефоне, поэтому ваш собственный VPN продолжает работать
  вместе с ним.
- **Обновляйте заблокированные точки входа:** Если точки входа сервера пересылки проекта изменились
  и устройство не может до них достучаться, экспортируйте подписанные точки входа с подключённого
  компьютера командой `cbb global entries export` (или `-qr`) и импортируйте их на затронутом
  компьютере командой `sudo cbb global entries import STRING`.
- **Проверяйте причины сбоев:** Выполните `cbb global` на ноутбуке, чтобы увидеть, почему туннель
  не сработал, и включите `CBB_DEBUG=1` для службы, чтобы посмотреть журнал рукопожатий WireGuard
  ([Решение проблем: синхронизация вне дома](troubleshooting.md#sync-away-from-home)).
